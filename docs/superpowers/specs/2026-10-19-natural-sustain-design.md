# 长音自然延音设计文档

日期：2026-10-19
状态：方向已确认（2026-10-19 brainstorming 会话），builder 检查已完成

## 意图与背景

长 `duration` 音符目前听起来不自然，有两个问题，均由用户反馈并经实测确认：

1. **循环重复感可闻。** 延音循环是一个固定窗口（采样的 45%–95%，约每 1.56 秒一圈），
   每圈内容完全相同。窗口内任何周期性特征都会被反复听到。
2. **响度轨迹不自然。** 增益包络先满音量平走到采样 95% 处，再指数衰减。真钢琴从
   击弦那一刻起就持续衰减。更糟的是：采样在循环窗口内部本身就在自然衰减，每次
   循环回卷都会把音量跳回较大处——每约 1.56 秒一次可闻的锯齿状起伏。

实测事实（2026-10-19，直接取自 CDN 采样）：

- 88 个采样全部为立体声、44.1 kHz、统一裁到约 3.13 秒。
- 各音区衰减速度差异巨大：A0 约 3.5 dB/s，C4 约 10 dB/s。
- 高音在采样内部就真实消亡：C6 约 1.4 秒后只剩本底噪音，C8 约 1.0 秒。
  对这些音，现有循环窗口循环的几乎是静音。

## 目标

- 按住超过采样长度的音符持续发声，响度从起音到静音遵循一条连续的、
  符合该音符自身的自然衰减曲线。
- 循环回卷处无可闻的周期性或音量跳变。
- 真实延音短于采样的音（高音区）自然消亡，而不是被人为延长。
- 延音踏板（`pedalDown`/`_extendVoice`）使用同一套机制，听感一致。

## 非目标

- 不改变短 duration（断奏）路径和不传 duration 路径的行为。
- 不改变 CDN 采样格式、加载管线、音高模型或公开 API
  （`oneShot(step, octave, alter, duration)` 签名保持不变）。
- 不做力度分层、多重采样、共鸣、制音器噪音。

## 反目标（即使"能跑"也算失败）

- 长音听得出"先平走再陡降"。
- 长音的循环周期能被听出来。
- C8 类高音在真实消亡之后还在嘶响或嗡鸣。
- 加载时急切处理全部 88 个音（内存爆炸）；分析和循环缓冲必须按音懒构建、
  首次长音使用时构建并缓存。

## 约束

- 纯 ES6 JavaScript，仅 Web Audio API；不加 IE shim（仓库约定）。
- `dist/` 需要提交：`npm run build` 的产物随本次改动一起提交。
- `window.LitePiano` 全局变量和 `keyboard.keyborad` 拼写是公开契约——不动。
- 仓库没有自动化测试之外的遗留设施；验证方式为 `npm run build` + demo 页
  人工试听。听感判断由用户完成，实现者负责说明"听什么"。

## 设计

全部改动位于 `src/index.js` 与新增的纯函数模块 `src/sustain.js`。三个部分：
按音包络分析、处理过的循环缓冲、新的长音增益包络。

### 1. 按音包络分析（懒构建，带缓存）

在某个音首次以长 duration 使用时，分析其解码后的 `AudioBuffer`：

- 混成单声道，按 50ms 窗口计算 RMS；全程用 dB。
- 找到起音峰值窗口（`peakTime`、`peakDb`）。
- `audibleEnd` = 电平高于 `max(peakDb - 55 dB, -78 dBFS)` 的最后一个窗口。
  （早期草案用"最后 200ms 中位数 + 8 dB"作为本底；那把仍在鸣响时被裁剪的
  低音误判——A0 在采样末尾仍有约 -39 dBFS。-78 dBFS 的绝对下限用来区分
  真实的 16-bit 本底噪音和"轻但还活着"的信号。）
- 衰减率：对 `peakTime + 0.3s` 到 `audibleEnd` 之间的窗口做 dB-时间线性拟合，
  记为 `decayDbPerSec`（正数），钳制在 [0.5, 60] dB/s。

分类：

- **消亡型音符**：`audibleEnd - peakTime < 0.8s`，或可用循环窗口（见下）
  不足 0.4s。永远不构建循环。长 duration 直接播放原始采样、任其消亡
  （C8 的行为：约 1 秒后真实地静音）。
- **延音型音符**：其余全部。

分析结果按音名缓存。

### 2. 处理过的循环缓冲（"去倾斜"，无缝）

对延音型音符，构建采样的副本：

- **循环窗口**：`loopStart = max(peakTime + 0.15s, audibleEnd - 1.2s)`，
  `loopEnd = audibleEnd - 0.05s`（在采样消亡前留边距）。典型结果是稳定延音区
  一段约 1.1–1.5s 的窗口。
- **去倾斜**：在窗口内应用一条恰好抵消实测衰减的增益斜坡
  （`gain(t) = 10^(decayDbPerSec · t / 20)`，在 `loopStart` 处归一为 1.0）。
  去倾斜后窗口电平平稳，首尾电平一致，回卷不再有音量跳变。
- **接缝**：沿用现有的烘焙交叉淡化手法（现有 `_createSustainBuffer`）：
  `loopEnd` 前最后约 80ms 与 `loopStart` 前的素材做形变混合，波形本身
  无缝回卷、无咔哒声。

处理后的缓冲与分析结果一起按音缓存。原始解码缓冲永不被修改
（短音路径和不传 duration 路径继续使用它）。

### 3. 长音的分支与增益包络

分支判定（分析是懒构建带缓存的；预过滤避免断奏触发分析）：

- `seconds ≤ 0.9 × natural` → 短音路径，不变，不做分析。
- 否则运行按音分析，然后：
  - 延音型 **且** `seconds > audibleEnd` → 循环路径（见下）；
  - 其余（消亡型，或 duration 在可听区域内结束）→ 播放原始采样；若在
    `endAt` 仍在发声，则在 `endAt` 做释放淡化。消亡型音符配长 duration
    会自己消亡。

循环路径（延音型音符）：

- 播放处理后的缓冲，`loop = true`，`loopStart`/`loopEnd` 如上。
- 从音符开始（音频时钟 `startTime`）到 `startTime + loopStart` 增益为 1.0
  （原始起音和早期衰减自然播放）。
- 从 `startTime + loopStart` 起，用 `exponentialRampToValueAtTime` 按实测速率
  向听不见的方向衰减——外部包络恰好补回被去倾斜抹掉的衰减。由构造可知，
  每次回卷处的电平等于原始采样自然播放到该处的电平——回卷不仅无咔哒声，
  而且电平连续。
- 衰减率是音符的属性，绝不为凑某个deadline重新调斜率。在
  `endAt = startTime + duration` 处：若仍可闻，接现有的短释放淡化
  （`RELEASE_SECONDS`，如同制音器落下）；若包络早已衰减到不可闻（约 -60 dB），
  提前停掉 source 以省 CPU。

因为去倾斜 + 匹配包络重建了自然轨迹，循环内容即使重复也没有响度锯齿；
残余的周期性被持续下落的电平掩盖。

### 4. 踏板路径

`_extendVoice` 职责不变（延长到 `SUSTAIN_SECONDS`），但用新机制重新表达：

- 衰减率永不改变。踏板延长只移动停止时间：已在循环的 voice 保持其实测速率
  包络继续走；释放淡化和 source 停止时间重排到
  `startedAt + max(seconds, SUSTAIN_SECONDS)`。（真钢琴的踏板不改变琴弦衰减
  速度，只让它继续响。明确拒绝"把衰减重新调斜到恰好在新 `endAt` 归零"。）
- 被踏板接住、尚未循环的 voice 照旧换到处理后的循环缓冲，**但**新 voice 的
  增益初始化为按已发声时长计算的自然电平——
  `10^(-decayDbPerSec · (noteTime - loopStart) / 20)`，钳制 ≤ 1.0——而不是
  淡到满音量，swap 处不发生音量回跳。
- 消亡型音符忽略踏板延长——踏板无法复活一根已经停振的弦。

### 5. 保持不变的部分

- 短 duration 路径：原始采样 + note-off 淡化（不变）。
- 不传 duration 路径：原始采样，鸣响到自然衰减（不变）。
- `resume()`、`load()`、状态机、并发、UMD/全局契约。

## 实现者自决项（我的判断，非用户决定）

- 50ms RMS 窗口；`max(peak - 55 dB, -78 dBFS)` 作为可听阈值；0.8s/0.4s 的
  消亡型 cutoff；1.2s 目标循环长度；80ms 接缝交叉淡化；-60 dB 作为"不可闻"。
  全部为文件顶部常量，试听后可调。
- 衰减用 `exponentialRampToValueAtTime`（精确的 dB 线性）而非 `setTargetAtTime`。
- 按音懒处理（内存有界），不 eager 处理全部 88 个。
- 消亡型音符忽略踏板，而不是循环噪音。
- （builder 检查决议）踏板延长只移动停止时间、永不动衰减率；踏板换缓冲时
  增益初始化为按已发声时长计算的自然电平；长音分支先用 `0.9 × natural`
  预过滤再分析；消亡型或窗口过短的中间长度 duration 回落到原始采样 +
  释放淡化。
